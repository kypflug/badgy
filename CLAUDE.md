# Agent guide — Badgy

An installable attendance **calendar** for RTO/badge-in planning, with **preconfigured
return-to-office policies for a dozen large employers**. Each user's data lives **privately in a
hidden per-app folder in their own cloud storage** — OneDrive via Microsoft Graph, or Google Drive's
`appDataFolder` — and syncs with a **CRDT**. An Azure Functions token-mediator handles auth only;
attendance data never transits it.

## First actions
1. `nvm use` (Node 24) then `npm install`.
2. `@badgy/shared` builds before `web` typecheck. The API has its own dependency tree:
   `npm --prefix packages/api install`.
3. Validate web/shared with `npm run gates`; validate auth changes with
   `npm --prefix packages/api run build` and `npm --prefix packages/api test`.
4. `data/` is compiled into `packages/shared/src/generated/` (gitignored) by `npm run gen:data`,
   which `gates`/`typecheck`/`build`/`test` run automatically via `pre*` hooks.

## Layout
- `data/` — **community-contributable JSON**: `orgs/*.json` (employer policy presets),
  `holidays/*.json` (holiday rule sets), `schema/*.json` (JSON Schema). `data/README.md` is the
  contributor guide. Never edit `packages/shared/src/generated/` by hand.
- `packages/shared` — **source of truth**: taxonomy (`types.ts`), the policy engine
  (`policy/types.ts` taxonomy, `policy/engine.ts` evaluation, `policy/planner.ts` what-if,
  `policy/registry.ts` presets), BELT's pinned numeric core (`belt.ts`), date/calendar utils +
  meetup registry (`calendar.ts`), the holiday rule engine (`holidays.ts`), and the **CRDT sync
  core** (`sync/hlc.ts`, `sync/doc.ts`). Heavily unit-tested.
- `packages/web` — Lit + esbuild SPA + PWA.
  - `auth/provider.ts` — multi-provider BFF session + auth transaction client;
    `sync/` — direct Graph (`graph.ts`) and Google Drive (`google-drive.ts`) app-folder transports
    plus a dev mock.
  - `org/` — `resolve.ts` (workplace routing) and `org-picker.ts` (plain-DOM chooser).
  - `state/store.ts` — sync engine + calendar API over the doc (optimistic edits → debounced
    pull/merge/push; localStorage = offline cache, keyed `badgy:doc:<provider>:<id>`).
  - `components/` — `badgy-app` (Workbench shell + month/year switching), `score-rail` (score,
    forecast, totals and account), `month-calendar` (detailed grid), `year-planner` (12 compact dot
    months), shared click menu + **drag-select** range toolbar, and `settings-page` (in-frame
    settings destination with policy draft/effect flow).
  - `lib/` — status meta, theme (Light/Dark/System), format, provider glyphs, `.ics` holiday
    import. `sw.ts` — service worker.
  - `public/` — manifest, icons (generated by `scripts/gen-icons.mjs`), `favicon.svg`.
- `packages/api` — Azure Functions v4 token mediator, CommonJS with extensionless imports.
  - `lib/providers/` — `microsoft.ts` (wraps MSAL) and `google.ts` (hand-rolled OAuth, no new deps)
    behind one `AuthProvider` interface.
  - `/auth/start` takes a `provider` and creates a short-lived server-side PKCE transaction; the
    original app polls `/auth/complete`, which sets its HttpOnly session cookie after the callback
    succeeds. **Don't collapse this back to a cookie-bound callback — it is the Safari/iOS fix.**
  - `/auth/me`, `/auth/logout`, and `/token` manage session health and short-lived access tokens.
  - Token caches and auth transactions are encrypted in Azure Table Storage, namespaced by
    provider. Never log tokens, cookies, polling secrets, or personal data.

## Data model (don't break)
- Sparse CRDT doc of **overrides**, keyed per ISO date (`d|YYYY-MM-DD`) + weekly pattern (`pat|<0-6>`)
  + meetup (`m|<Sun>`) + holiday (`h|YYYY-MM-DD`, boolean or a display name) + note (`n|<uuid>`)
  + `cfg|targetBelt`, `cfg|holidayRegion`, `cfg|org`, `cfg|scheme` (a JSON `ComplianceScheme`).
  Unset days resolve from defaults: holiday→holiday, configured pattern, unconfigured
  weekend→none, else office. `merge` must stay commutative + idempotent; every write gets a fresh
  `hlc.tick()`. `migrate()` upgrades v1 weekly-grid docs. New `cfg|` keys are additive.
- **Taxonomy:** office/remote/travel/vacation/sick/holiday/oof (+ `none`). Display order is In office,
  Remote, Business Travel, Time off, Sick, Holiday, Other. Only `office` counts toward the score
  unless a policy sets `travelCountsAsOffice`.
- **Org presets seed, never lock.** `cfg|org` is written only after the first successful pull proves
  it is unset, so the URL a returning user opens can't overwrite a workplace they already chose.

## Policy engine
Six scheme kinds, all normalising to a `0..1` attainment ratio plus a period series so the ring,
sparkline, bands and planner are scheme-agnostic: `best-of-window` (BELT), `qualifying-weeks`,
`weekly-quota` (covers 5-day mandates), `period-quota`, `period-percentage`, `none`.
Each carries `bands` and an `absence` policy (`excused` statuses, `travelCountsAsOffice`,
`proration: 'prorate' | 'ignore'` — BELT uses `ignore` because its window *is* the allowance).

**BELT is a behavioural contract.** `belt.ts` and `src/__fixtures__/belt-parity.json` are pinned;
`policy/engine.test.ts` asserts the generic engine reproduces them exactly. If they disagree, the
engine is wrong — never the fixture.

Presets declare `confidence` (`official`/`reported`/`community`), `sources[]` and `assumptions[]`.
Most employers never publish their measurement window, so **never present a guess as fact**: any
inferred parameter must be listed in `assumptions[]` and is surfaced in Settings.

## Workplace routing
`org/resolve.ts` resolves hostname first label → first path segment → `?org=` → remembered choice →
`generic`, then cleans the URL with `history.replaceState`. Path routing (`badgy.tech/amazon`) is
what ships; hostname is checked first so a sub-domain later needs only DNS. **Azure Static Web Apps
caps custom domains at 5 with no wildcard**, so sub-domains don't scale without Front Door.

## Conventions
TypeScript, ESM, `verbatimModuleSyntax` (`import type`), `.js` on relative imports — except
`packages/api`, which is CommonJS with extensionless imports. Lit without decorators; Biome +
stylelint; Playwright + vitest; LF everywhere. Style **only** with Badgy tokens from
`styles/tokens.css` (`var(--badgy-…)`) — never hardcode a colour in a component; warm-paper light
and warm-charcoal dark palettes, 8–14px radii (no `corner-shape`), and a single major shadow on the
Workbench frame only — interior separation is hairlines and value steps. Band
classes are `.score-danger` / `.score-warning` / `.score-success`.

## Holidays
`holidays.ts` is a rule *engine*; the rule *data* lives in `data/holidays/*.json` as rules (fixed
date, nth/last weekday, Easter offset, weekend observance, `fixed-or-nth-weekday`), never date
tables, so any year resolves. `us-microsoft` is the default set and its output for 2026/2027 is
pinned by a parity test — don't change those rules casually. Users layer `h|` overrides on top via
Settings, including `.ics` import.

## Deploy
Push `main` to run `.github/workflows/deploy.yml`, which builds web + API and deploys both to
**Azure Static Web Apps**. Microsoft is a confidential web client and Google a web OAuth client,
both with callback `https://badgy.tech/api/auth/callback`; secrets and encryption/storage settings
live in SWA app settings. **Google sign-in ships hidden behind the `GOOGLE_ENABLED` build flag**
(default `'false'`) because `drive.appdata` is a sensitive scope and unverified apps cap at 100
users — the transport and BFF provider ship either way, so enabling it is a flag flip plus two app
settings. See `docs/SETUP.md`.
