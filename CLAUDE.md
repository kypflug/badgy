# Agent guide — Badgy

An installable attendance **calendar** for RTO/badge-in planning. Each user's data lives
**privately in their own OneDrive app folder** via Microsoft Graph and syncs with a **CRDT**.
An Azure Functions token-mediator handles Microsoft auth only; attendance data never transits it.

## First actions
1. `nvm use` (Node 24) then `npm install`.
2. `@rto/shared` builds before `web` typecheck. The API has its own dependency tree:
   `npm --prefix packages/api install`.
3. Validate web/shared with `npm run gates`; validate auth changes with
   `npm --prefix packages/api run build` and `npm --prefix packages/api test`.

## Layout
- `packages/shared` — **source of truth**: taxonomy (`types.ts`), BELT (`belt.ts`), date/calendar utils
  + holidays + meetup registry (`calendar.ts`), `compliance.ts` (rolling BELT, actual vs projected),
  `planner.ts`, and the **CRDT sync core** (`sync/hlc.ts`, `sync/doc.ts`). Heavily unit-tested.
- `packages/web` — Lit + esbuild SPA + PWA.
  - `auth/` — BFF session + dock-app auth transaction client; `sync/` — direct Graph app-folder
    transport + dev mock.
  - `state/store.ts` — sync engine + calendar API over the doc (optimistic edits → debounced
    pull/merge/push; localStorage = offline cache).
  - `components/` — `rto-app` (shell + month/year switching), `month-calendar` (detailed grid),
    `year-planner` (12 compact months + annual status totals), shared click menu + **drag-select**
    range toolbar, `compliance-bar` (ring + planner), `settings-dialog` (usual week, target, meetup,
    theme, import, account).
  - `lib/` — status meta, theme (Light/Dark/System), format, xlsx import. `sw.ts` — service worker.
  - `public/` — manifest, icons (generated by `scripts/gen-icons.mjs`), `favicon.svg`.
- `packages/api` — Azure Functions v4 token mediator.
  - `/auth/start` creates a short-lived server-side PKCE transaction; the original app polls
    `/auth/complete`, which sets its HttpOnly session cookie after the callback succeeds.
  - `/auth/me`, `/auth/logout`, and `/token` manage session health and short-lived Graph tokens.
  - MSAL caches and auth transactions are encrypted in Azure Table Storage. Never log tokens,
    cookies, polling secrets, or personal data.

## Data model (don't break)
- Sparse CRDT doc of **overrides**, keyed per ISO date (`d|YYYY-MM-DD`) + weekly pattern (`pat|<0-6>`)
  + meetup (`m|<Sun>`) + `cfg|targetBelt`. Unset days resolve from defaults: holiday→holiday,
  configured pattern, unconfigured weekend→none, else office. `merge` must stay commutative + idempotent;
  every write gets a fresh `hlc.tick()`. `migrate()` upgrades v1 weekly-grid docs.
- **Taxonomy:** office/remote/travel/vacation/sick/holiday/oof (+ `none`). Display order is In office,
  Remote, Business Travel, Time off, Sick, Holiday, Other. Only `office` counts toward BELT.
- **BELT:** Sunday-start weeks; count all office days but cap each week at 5; rolling best-8-of-12 ÷5;
  bands 80/90. Past=actual, future=forecast (today boundary).

## Conventions (mirror `theseus`)
TypeScript, ESM, `verbatimModuleSyntax` (`import type`). Lit for UI; Biome + stylelint; Playwright +
vitest. Style **only** with MAI tokens (`var(--smtc-…)`); large squircle radii; AI gradient reserved
for the brand mark / accents.

## Deploy
Push `main` to run `.github/workflows/deploy.yml`, which builds web + API and deploys both to
**Azure Static Web Apps**. The app registration is a confidential web client with callback
`https://badgy.tech/api/auth/callback`; secrets and encryption/storage settings live in SWA app
settings. See `docs/SETUP.md`.
